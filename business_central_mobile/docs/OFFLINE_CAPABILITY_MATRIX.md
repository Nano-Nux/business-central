# Mobile offline capability matrix

| Capability | ONLINE connected | ONLINE temporary-offline | FULLY_OFFLINE | Conflict policy |
|---|---|---|---|---|
| Authentication | Backend login/refresh/logout | No refresh request while disconnected | Local owner login | Local credential verification; no client-wins server policy |
| Merchant/shop context | Backend authoritative | Cached read only | Local scoped rows | Explicit tenant/shop scope |
| Read cache | SQLite cache refreshed from backend | Merchant/workspace and catalog reads use SQLite when transport is denied | Local scoped rows only | Server reconciliation for ONLINE |
| Local backup/restore | Not used for backend state | Not used for disconnected server reconciliation | Merchant-scoped operational JSON export/restore after local authentication | Schema-version and merchant-scope validation; credentials are never exported |
| Local audit events | Backend audit_events on connected mutations | No disconnected server audit upload | Append-only merchant/shop/actor-scoped events for sensitive local mutations; included in backup/restore | No client update/delete API; future reconciliation must preserve event identity and ordering |
| Catalog search | Backend categories/products | Cached categories/products only | Local merchant-scoped categories/products/variants | Reject cross-merchant data; local rows are standalone truth |
| Catalog administration/pricing | Backend-authoritative CRUD and price writes | Disabled while disconnected | Local category/product/variant and merchant price-list/price CRUD | Local catalog/pricing has no backend reconciliation or local price-history claim |
| Measurement units/conversions | Backend-authoritative merchant unit/conversion CRUD | Disabled while disconnected | Merchant-scoped local unit/conversion CRUD with validation | Local data has no cross-domain backend reconciliation or variant base-unit policy yet |
| Inventory locations | Backend authoritative selected-shop locations | Cached selected-shop locations | Local setup location | Merchant/shop-scoped rows; local balances are maintained only by the local ledger |
| Inventory movement history/detail | Backend-authoritative selected-shop immutable ledger and FIFO/document detail | Disabled until movement cache freshness and scope invalidation are defined | Local stock-in and POS stock-out movement/detail with purchase-order/receipt/batch/expiry context and FIFO allocations | Standalone local ledger; no backend FIFO reconciliation |
| Stock receiving | Backend-authoritative FIFO receipt and movement | Disabled until durable inventory operation policy exists | Local exact quantity/cost receipt, optional purchase-order/receipt/batch/expiry context, FIFO layer creation, and event-key idempotency | Standalone local ledger; no backend FIFO reconciliation |
| POS cart/quote/checkout | Backend catalog, authoritative quote, and idempotent order checkout | Disabled for quote/payment/checkout; cached catalog may be displayed only when explicitly wired | Local catalog, exact local quote, atomic local order, FIFO stock consumption, and captured local payment record | Standalone local truth; no backend reconciliation or external payment capture |
| Reports | Backend-authoritative selected-shop aggregates | Disabled until report cache freshness and invalidation are defined | Local sales summary/day/top-product reads from local orders and FIFO allocations, with COGS, refund totals, refund-adjusted gross profit/margin for tracked stock | Standalone local totals; untracked-stock provenance remains pending |
| Transaction history | Backend-authoritative selected-shop events and details | Disabled until durable event cache policy exists | Local order, inventory movement, POS refund, and repair checkout/refund events/details with FIFO cost/profit and payment projections | Preserve standalone local identities; backend reconciliation remains unclaimed |
| Delivery options | Backend shop-scoped CRUD | Disabled for create/delete while disconnected | Merchant/shop-scoped local option CRUD and POS selection | No temporary-offline reconciliation or delivery fee policy yet |
| Invoices | Backend-authoritative canonical invoice read | Disabled until a durable immutable invoice cache is defined | Local invoice projection from local orders/lines and repair service/part records with native PDF/print/share plus device-local image-first Bluetooth ESC/POS output | Standalone local invoice; no canonical server numbering or reconciliation claim |
| Customer history | Derived from backend invoices and repair orders | Disabled until source caches have a consistent freshness policy | Derived from local order and repair customer fields | Read projection only; no client-owned customer truth |
| Staff account management | Backend membership and role authority | Disabled while disconnected | Local Argon2id identity/membership provisioning, shop assignment, active-state changes, role-permission editing, and shop-module controls | Merchant-scoped local authorization; permission-definition creation and reconciliation remain pending |
| Repair intake | Backend atomic ticket command | Disabled; repair intake has lifecycle/payment/inventory effects | Local merchant/shop-scoped intake with diagnostics, balance-checked payment/refund records, parts, images, approvals, warranties, lifecycle status, used catalog-part FIFO consumption, and part-based total recalculation | Standalone local repair ledger; no external payment capture or backend reconciliation |
| Shop settings | Backend-authoritative profile/tax/receipt settings | Selected-shop updates commit to SQLite and a durable queue row; reconnect push/pull reconciles with explicit conflict/rejection states | Local merchant/shop profile, timezone, tax, and receipt settings | Optimistic base-version conflict; server-authoritative conflict payload |
| Repair specifications | Portal-local fault presets and default intake duration | Local SQLite only; no backend contract exists to queue | Merchant/shop-scoped local presets and duration | Local setting replacement with append-only audit; no backend reconciliation claim |
| Promotions | Backend-authoritative definitions, schedules, codes, scopes, and POS promotion reference | Disabled for create/delete while disconnected | Local merchant-scoped definitions, schedules, codes, scopes, usage validation, and exact POS application | Standalone local promotion/order redemption history; no ONLINE reconciliation |
| Service catalog/orders | Backend-authoritative service definitions, orders, items, appointments, notes, and billing records | Disabled while disconnected until a durable mutation policy exists | Local merchant-scoped service definitions, shop-scoped orders, items, appointments, notes, and standalone billing records | Local service records are standalone; billing does not capture external payment and no backend reconciliation is claimed |
| Supported mutation queue | Backend or transactional local queue | Queue only after entity policy exists | Never queued for backend sync | Entity-specific policy required |
| External payment capture | Backend only | Disabled | Disabled until local policy exists | Reject; no silent client-wins |
| Permission/module changes | Backend only | Disabled | Local owner can assign existing permission definitions to merchant-scoped roles and enable/disable merchant-enabled modules per shop; definition creation remains disabled | Repository-level `rbac.manage` checks, explicit audit, and no ONLINE reconciliation |
| Inventory-affecting POS | Backend authority | Disabled until stock conflict policy exists | Enabled for local stock-tracked variants through atomic local checkout | Standalone local ledger; stock receiving and reconciliation remain pending |
| Repair lifecycle | Backend authority | Pending contract pairing | Local status transitions and payment balance records | Standalone local lifecycle; reconciliation requires an explicit future policy |

This matrix is intentionally conservative. A screen is not offline-capable
merely because it can display cached data.
