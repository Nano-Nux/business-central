# Portal Offline Audit

Last verified: 2026-08-10

The portal has two mutation policies:

- Typed operations use the canonical sync handshake/push/pull protocol.
- Deferred operations store the exact currently exposed portal API request in
  the same IndexedDB transaction as the local projection. They use stable
  idempotency keys, dependency ordering, local-ID remapping, retry/backoff,
  durable rejection/conflict states, and foreground/reconnect replay.

All cached reads are merchant- and membership-scoped. IndexedDB survives
refresh, browser restart, and service-worker replacement. Service-worker
background sync is only a wake-up hint; launch, reconnect, and manual sync are
authoritative.
